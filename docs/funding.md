# Funding design: handling long/short imbalance

**Problem.** In a "short the trenches" product, most users want to short. A pool that is 95% short gives shorts almost nothing when they win, and a pool that is 100% short is refunded. Either way there is no product.

## Mechanism

Funding is charged once per round, from the totals at the moment deposits close (`L` = long total, `S` = short total).

```
skew      = |S − L| / (S + L)                     in [0, 1]
rate      = min(fundingMax, k × skew)              k = 10%, fundingMax = 5%
F         = min(rate × crowded, fundingCap × minority)   fundingCap = 50%
effective = crowded − F ,  minority + F
```

Then, using the effective stakes:

```
transfer  = min(effLoser, effWinner × maxProfit)   maxProfit = 5×
fee       = transfer × 2%
winners  <- effWinner + transfer − fee     (pro-rata by raw stake)
losers   <- effLoser − transfer            (non-zero only when the cap binds)
```

**Invariant (fuzz-tested in Solidity and TypeScript):** `longPayout + shortPayout + fee == L + S`, with rounding always in the pool's favour.

## Why this shape

- **One-shot rather than continuous funding:** a round is only one hour, so there is no position to charge funding on over time.
- **Proportional to skew:** a balanced pool pays nothing, and a lopsided one pays up to 5%.
- **Minority cap at 50%** stops someone depositing 0.01 HYPE against 500 HYPE and collecting a large guaranteed payment.
- **Outcome-independent:** the minority side gets paid even when it loses. This is what pulls market makers and arbitrageurs onto the empty side.

## Alternatives considered

| Option | Verdict |
|---|---|
| No funding, pure pari-mutuel | Already self-balancing through the odds, but gives no guaranteed incentive, so empty sides stay empty more often |
| Protocol-seeded minority side | Turns the protocol into a counterparty and creates insolvency risk. Rejected for v1 |
| Asymmetric fees (crowded side pays a higher fee) | Similar effect, but only when the crowded side wins. Weaker |
| Dynamic deposit caps on the crowded side | Bad UX ("pool full"), though worth considering as a v2 complement |
